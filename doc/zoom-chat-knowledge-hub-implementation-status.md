# Zoom Chat Knowledge Hub — MVP 实施状态

> 更新日期：2026-10-01  
> 注意：PRD v0.2 已确认新的自动知识沉淀方案；下述“v0.2 待实施差距”用于区分目标设计与当前代码。

日期：2026-09-30

## 已实现

- 本地只读 Web 应用（FastAPI + SQLite + 原生前端），只监听 `127.0.0.1:8765`。
- 导入现有 Zoom OAuth 授权，并使用 Windows DPAPI 保存受保护副本。
- 获取当前授权用户的全部 Zoom Team Chat 群组。
- 对群组进行正文状态检测：`readable`、`encrypted`、`mixed`、`unknown_no_messages`、`forbidden`、`missing`、`error`。
- 按群组选择是否纳入同步；选择只保存在本地。
- 每个群独立增量游标，回退 5 分钟读取并通过 `(channel_id, zoom_message_id)` 去重。
- “群组与可读性”支持 30/90/180 天首次同步范围，默认 90 天。
- 明确记录首次同步完成、历史覆盖起点和累计同步水位；扩大范围时由用户显式补读，缩小范围不删除数据。
- 消息正文和回复关系本地存储；附件只保存元数据，不下载附件内容。
- `@我` 识别和本地待处理状态（new / in_progress / done / ignored）。
- 从可读消息中提取问题候选，关联同群后续回复，并以本地文本相似度合并重复问法。
- 知识候选人工审核：编辑归一化答案、分类，并标记 candidate / approved / rejected / stale。
- 概览、群组与可读性、消息查询、知识库、@我、设置六个 UI 页面。

## v0.2 已确认、待实施

- 一次性扫描本地历史消息，将最后活动早于成熟阈值的话题直接写入知识库，不经过可见 Conversation Topics。
- 默认成熟阈值为 14 天，可选 7/14/30 天；每次同步后自动归档达到静默阈值的近期 Topic。
- 知识标题、问题和结果按原始对话语言保存，不生成永久翻译副本。
- 查询阶段检测语言并临时生成另一语言查询，结合关键词、结构化字段和多语言 embedding 检索；翻译查询不落库。
- Conversation Topics 中以 `Search KB` 替换 `Add to KB`，显示相似知识但不手动改变归档状态。
- `Do not track` Topic、同线程回复和高度重叠后续版本不进入历史或增量知识归档。
- Knowledge Base 默认列出最近新增、最近更新、未解决和有新活动的知识标题。
- 历史导入需要 checkpoint、幂等、断点续传和可见进度；知识更新需要不可变版本和 conflict/related 关系。

当前代码中的一键 `Add to KB`、既有知识候选逻辑和语言输出设置属于过渡实现，后续应按 PRD v0.2 替换；本次仅更新文档，未修改代码。
- 加密消息正文无法通过当前 Zoom API 授权解密；工具会保留其状态和元数据，不猜测正文。
- 当前为单机单用户版本，SQLite 中保存可读消息正文，部署前需要确认公司留存和访问控制要求。
- 当前不会向 Zoom 发送消息、修改已读状态或下载附件。

## v0.2 实施更新（2026-10-01）

已完成并部署到本地服务：

- 知识成熟期可选 7/14/30 天，默认 14 天。
- 最近 Topic 按原始对话语言总结，仅在成熟期内显示于 Conversation Topics。
- 同步后自动提取近期 Topic，并分批归档达到成熟期的 Topic。
- 历史建库直接扫描本地旧消息，排除 `Do not track` 来源，支持幂等分批、失败重试和状态显示。
- 知识记录原始语言、结论状态、原始 Zoom 消息证据和不可变 JSON 版本快照。
- Conversation Topics 已用 `Search KB` 替换 `Add to KB`。
- 知识查询临时生成中英文查询变体，不保存翻译副本。
- Knowledge Base 默认按最近更新排序，仍保留可选的人工纠错编辑。

已在真实数据库副本验证：1,839 条消息、32 个既有 Topic 和 14 条既有知识均保留；当前识别出 71 个可分批导入的历史窗口。自动化测试 14 项全部通过。
